# AI Design Workspace（暂定）PRD

## 0. 文档说明

本文档基于 `docs/requirements.md` 编写，用于定义一个类似 Claude Design 的 AI 设计生成网站的产品需求、用户流程、页面框架、交互逻辑、视觉方向、状态设计和验收标准。

本文档只讨论产品功能、用户体验、页面框架、状态和验收标准，不讨论工程实现、数据结构、接口、模型、部署或框架选型。涉及不明确或存在产品取舍的内容，统一放入「12. 待确认问题」，并给出推荐默认方案。

视觉参考仅参考 Claude 登录页 / Claude Design 的整体气质：简洁、克制、温暖浅色、卡片式、留白充足、专业可信赖。不复制其品牌、Logo、文案、商标或受保护视觉资产。

## 1. 产品概述

### 1.1 产品名称

AI Design Workspace（暂定）

正式产品名称待确认。当前名称只用于 PRD 表达产品范围。

### 1.2 一句话产品定位

一个通过自然语言生成、预览、迭代修改和导出多页面网页 / 应用原型的 AI 设计工作台。

### 1.3 目标用户

- 个人创作者：希望快速把想法变成可点击原型，用于自我验证、演示或内容创作。
- 前端开发者：希望把 AI 生成的多页面原型作为后续开发起点。
- 产品经理 / 运营人员：希望用文字描述快速生成页面流程，用于需求沟通、活动页构思或业务方案展示。
- 设计师：希望通过自然语言快速探索多个界面方向，再进一步细化。
- MVP 阶段的单人使用者 / 管理员：既是主要用户，也是项目、额度和内容的管理者。

### 1.4 核心使用场景

- 从一句产品想法生成多页面原型。
- 在工作台中查看页面清单、切换页面并预览页面跳转。
- 通过对话继续修改当前项目。
- 点击预览中的元素或区块后，对局部区域进行修改。
- 对整个页面或整个项目发起范围更大的修改。
- 查看版本历史，撤销不满意修改，回退到指定版本。
- 导出当前项目的静态结果或可继续编辑的项目结构。

### 1.5 MVP 范围

- 轻量账号与登录。
- 项目列表与项目归属。
- 自然语言输入生成多页面项目。
- 聊天 + 预览式 Design Workspace。
- 页面清单、页面切换、页面新增、删除、重命名、设置首页。
- 对话式修改。
- 点击元素 / 区块后的局部修改。
- 整个页面 / 整个项目范围修改。
- 项目级版本快照、预览历史版本、回退和撤销。
- 自动保存、手动保存、保存状态提示。
- 当前项目导出、导出前检查、导出成功 / 失败提示。
- 额度 / 使用次数记录与基础可见提示。

### 1.6 非 MVP 范围

- 完整订阅支付、发票、团队账单。
- 团队协作、多人实时编辑、复杂项目权限。
- 公开分享和可编辑分享。
- 完整图片理解、文件解析、网页抓取。
- Figma、设计系统、复杂设计稿导入。
- 任意框选区域修改。
- 分支版本、局部页面回退、跨版本合并。
- 真实后端业务逻辑、真实支付、真实权限系统、真实数据同步。
- 生产级代码质量承诺。

### 1.7 产品成功标准

- 用户能在首次登录后创建一个项目，并在同一工作区完成生成、预览、修改、保存和导出。
- 用户能理解当前项目包含哪些页面、当前预览的是哪个页面、页面之间如何跳转。
- 用户能通过自然语言修改项目，并看到修改影响的页面或区域。
- 用户能点击页面元素 / 区块并针对该区域发起修改。
- 用户能撤销不满意修改，或从历史版本恢复项目。
- 用户能导出当前版本，并清楚理解导出内容是原型或开发起点，不等于生产应用。
- 用户能看到额度 / 使用次数状态，理解高成本操作会被记录。

## 2. 用户角色

| 用户角色 | 为什么使用 | 最重要任务 | 痛点 | 产品如何解决 |
|---|---|---|---|---|
| 个人创作者 | 想快速把产品、页面或活动想法变成可展示原型 | 输入想法、生成多页面原型、反复修改、导出分享 | 不会设计或开发，传统设计工具启动成本高 | 用自然语言生成项目，在预览中直接修改和导出 |
| 前端开发者 | 想把模糊需求快速转成页面起点 | 生成页面结构、查看交互流程、导出可继续编辑项目 | 从零搭建页面耗时，需求经常不完整 | 自动规划页面、生成示例内容、导出项目结构 |
| 产品经理 / 运营人员 | 想把需求、活动或业务流程快速具象化 | 生成页面流程、修改文案和信息架构、演示方案 | 需求文档难以让团队形成共同画面 | 多页面预览、页面跳转、版本快照和导出让沟通更具体 |
| 设计师 | 想快速探索多个视觉和布局方向 | 生成初版、局部调整、尝试不同风格 | 空白画布探索慢，需求方反馈不精确 | 对话式修改和点击局部修改降低沟通成本 |
| 单人使用者 / 管理员 | MVP 阶段自己使用并管理项目和额度 | 登录、创建项目、保存、管理版本、控制使用量 | 项目容易丢失，模型调用成本不可见 | 轻量账号、项目归属、版本历史和额度记录 |

## 3. 核心用户流程

### 3.1 首次访问流程

1. 用户访问首页。
2. 用户查看产品定位、核心能力、示例展示和 CTA。
3. 用户点击「开始使用」。
4. 如果未登录，进入登录 / 轻量账号页。
5. 用户完成登录。
6. 系统跳转到项目列表页；如果带有 `returnTo` 场景，则跳转到原本要访问的页面。
7. 空项目用户看到新建项目入口和示例提示。

### 3.2 生成项目流程

1. 用户在项目列表页点击「新建项目」，或在首页 CTA 后进入新建项目入口。
2. 用户输入自然语言需求。
3. MVP 阶段可填写风格偏好文本；图片、文件、URL 输入只作为 P1 预留入口或提示，不进入完整闭环。
4. 用户点击「生成」。
5. 系统展示生成中状态，包括当前正在规划页面、生成页面、建立页面关系、保存版本等阶段性提示。
6. 生成成功后进入工作台。
7. 工作台展示页面清单、当前预览、对话面板、保存状态和初始版本快照。
8. 如果生成失败，用户看到失败原因、重试入口、保留原需求输入。

### 3.3 迭代修改流程

#### 3.3.1 对话描述修改

1. 用户在右侧对话 / 修改面板输入修改要求。
2. 系统识别修改范围：元素、区块、当前页面、多个页面或整个项目。
3. 系统在高风险场景提示影响范围，例如删除页面、全局重写、影响所有导航。
4. 用户确认后，系统进入修改中状态。
5. 修改完成后，预览更新，系统展示改动摘要并保存新版本快照。

#### 3.3.2 点击元素后局部修改

1. 用户在预览区进入选择模式。
2. 用户点击文本、按钮、卡片、表单、导航或页面区块。
3. 系统高亮选中元素，并在对话面板显示选区名称，例如「首页 / Hero 区块」。
4. 用户输入针对该选区的修改要求。
5. 系统默认只修改选区及其直接相关内容。
6. 如果文字要求扩大范围，系统提示影响范围。
7. 修改完成后，预览更新，版本快照生成，选区状态保留或更新。

#### 3.3.3 页面 / 项目范围修改

1. 用户在修改范围控件中选择「当前页面」或「整个项目」。
2. 用户输入修改要求，例如「把所有页面改成更商务的视觉风格」。
3. 系统展示将影响的页面数量和关键区域。
4. 用户确认后执行修改。
5. 修改完成后更新相关页面、页面地图和版本快照。

#### 3.3.4 撤销不满意修改

1. 用户点击「撤销上次修改」。
2. 系统展示将恢复到的版本摘要。
3. 用户确认后，项目恢复到上一个可用版本。
4. 系统创建一条新的当前版本记录，说明来自撤销操作。

#### 3.3.5 查看修改前后差异

1. 用户打开版本历史。
2. 用户选择两个相邻版本或一个历史版本与当前版本。
3. 系统展示差异摘要：页面新增 / 删除 / 重命名、修改区域、影响范围。
4. MVP 可先展示文本摘要和版本预览；更复杂的视觉 diff 放入后续版本。

### 3.4 多页面项目流程

1. 用户输入需求时可以指定多个页面，也可以只描述产品类型。
2. 系统自动生成页面地图，包含页面名称、用途和跳转关系。
3. 用户在左侧页面清单中查看全部页面。
4. 用户点击页面项切换当前预览。
5. 用户在预览内点击导航或按钮，系统跳转到对应页面。
6. 用户可以新增页面，系统同步页面清单和可用跳转目标。
7. 用户可以删除页面，系统提示受影响的导航入口和链接。
8. 用户可以重命名页面，系统同步页面清单、导航文案和相关跳转说明。
9. 页面之间的导航关系随项目保存和版本快照保存。

### 3.5 版本回退流程

| 方案 | 描述 | 优点 | 缺点 | MVP 建议 |
|---|---|---|---|---|
| 单个版本快照回退 | 每次生成 / 修改形成项目版本，用户恢复到某个版本 | 心智简单，覆盖全项目一致性，适合多页面 | 无法只恢复一个页面 | 推荐 |
| 整个项目回退 | 与单个版本快照基本一致，以项目整体为恢复单位 | 避免页面间状态不一致 | 粒度较粗 | 推荐作为 MVP 默认表达 |
| 局部页面回退 | 只恢复某个页面或区块 | 更灵活 | 容易破坏导航、共享元素和跨页面一致性 | 后续版本 |

MVP 推荐「整个项目版本快照回退」。原因：多页面项目存在导航、共享样式和对话上下文，局部回退容易造成状态不一致；项目级快照更容易让用户理解，也能覆盖撤销不满意修改的核心需求。

### 3.6 导出流程

1. 用户在工作台顶部操作栏点击「导出」。
2. 系统打开导出弹窗。
3. 用户选择导出类型：静态文件、可继续编辑的项目结构。
4. 系统展示导出前检查：当前版本、页面数量、是否有未保存修改、原型模拟说明、可能不包含真实后端能力。
5. 用户确认导出。
6. 系统进入导出中状态。
7. 导出成功后显示成功提示、导出版本、导出内容说明和下载 / 查看入口。
8. 导出失败时显示明确原因、重试入口，并说明当前项目和版本不会丢失。

## 4. 页面清单

### 4.1 登录页 / 轻量账号页

| 项目 | PRD 描述 |
|---|---|
| 页面目标 | 让用户完成轻量账号登录，并进入项目列表或 returnTo 页面 |
| 页面布局 | 左侧或上方展示产品价值与简短说明；右侧或中心展示登录卡片；移动端改为上下布局 |
| 输入项 | 邮箱；如采用密码登录则包含密码；如采用邮箱链接则包含邮箱和验证码 / 链接说明 |
| 按钮 | 继续使用邮箱、继续使用 Google（如启用）、继续使用 SSO（P1/P2）、返回首页 |
| 错误状态 | 邮箱格式错误、登录失败、验证码错误、链接过期、网络错误 |
| 成功状态 | 登录成功后显示短暂加载或直接跳转 |
| 空状态 | 输入框为空时主按钮禁用或点击后提示请输入邮箱 |
| 加载状态 | 按钮显示登录中，输入项不应重复提交 |

### 4.2 首页 / Landing Page

| 项目 | PRD 描述 |
|---|---|
| 首屏结构 | 顶部导航、产品名称、主标题、价值说明、主 CTA、次 CTA、温暖浅色背景 |
| 产品价值表达 | “用自然语言生成可预览、可修改、可导出的多页面原型” |
| CTA 按钮 | 主按钮「开始生成」；次按钮「查看示例」 |
| 示例展示区 | 展示一个工作台截图式示例：左侧页面清单、中间预览、右侧对话修改 |
| 登录后跳转 | 已登录用户点击 CTA 进入项目列表或新建项目；未登录用户进入登录页 |

### 4.3 工作台 / Design Workspace

| 区域 | PRD 描述 |
|---|---|
| 左侧项目 / 页面导航 | 展示项目名称、页面清单、当前页面、页面新增、删除、重命名、设置首页入口 |
| 中间实时预览区 | 展示当前页面，支持页面跳转、选择模式、响应式预览切换、空预览和错误状态 |
| 右侧对话 / 修改面板 | 展示对话历史、当前选区、修改范围选择、输入框、生成 / 修改按钮 |
| 顶部操作栏 | 项目名称、保存状态、撤销、版本历史、导出、账号入口 |
| 版本历史入口 | 顶部操作栏或右侧面板固定入口 |
| 导出入口 | 顶部右侧主操作区，避免隐藏在深层菜单 |
| 保存状态提示 | 顶部或底部状态区显示保存中、已保存、保存失败、离开提醒 |

### 4.4 项目列表页

| 项目 | PRD 描述 |
|---|---|
| 项目卡片展示 | 项目名称、描述摘要、最近更新时间、页面数量、版本数量、最近操作 |
| 新建项目 | 页面顶部主按钮和空状态主按钮均可新建项目 |
| 打开项目 | 点击项目卡片或「打开」按钮进入工作台 |
| 删除项目 | 项目卡片菜单中提供删除，需二次确认 |
| 空项目状态 | 显示产品说明、示例提示词和「创建第一个项目」按钮 |
| 搜索 / 排序 | MVP 可不做完整搜索；P1 支持搜索和最近更新排序 |

### 4.5 项目设置页

| 项目 | PRD 描述 |
|---|---|
| 项目名称 | 可编辑，修改后影响项目列表和工作台标题 |
| 项目描述 | 可编辑，用于项目摘要和后续上下文说明 |
| 默认风格 | MVP 可用文本描述保存；复杂品牌资产库后续再做 |
| 是否公开 | MVP 默认私有，不提供公开开关；公开分享作为后续能力 |
| 删除项目危险操作 | 独立危险区域，明确提示会删除项目、版本和导出记录 |

### 4.6 版本历史页 / 弹窗

| 项目 | PRD 描述 |
|---|---|
| 展示版本 | 时间、版本名称或自动摘要、触发指令、影响范围、页面数量 |
| 预览旧版本 | 用户选择版本后可预览，不立即覆盖当前项目 |
| 回退 | 用户点击「恢复此版本」后出现二次确认 |
| 风险提示 | 提示当前项目将切换到历史状态，恢复动作会生成新的当前版本记录 |
| 差异说明 | MVP 展示文本摘要：新增页面、删除页面、修改区域、全局变更 |

## 6. 每个功能的验收标准

### 6.1 账号与登录

#### AC-F-001 轻量账号登录

Given 用户在登录页输入有效账号信息  
When 用户点击「登录」或「继续」按钮  
Then 系统应显示登录中状态  
And 登录按钮在提交期间不可重复点击  
And 登录成功后跳转到项目列表页或 returnTo 页面  
And 页面顶部或账号入口显示已登录状态  
And 用户刷新页面后仍能保持登录状态

#### AC-F-002 登录状态保持

Given 用户已经完成登录并进入工作台  
When 用户刷新浏览器页面  
Then 系统应仍展示用户自己的项目内容  
And 不应回到登录页  
And 保存状态、当前项目和当前页面应保持可恢复  
And 如果登录状态已过期，系统应跳转登录页并保留 returnTo

#### AC-F-003 退出登录

Given 用户处于已登录状态  
When 用户点击账号菜单中的「退出登录」  
Then 系统应清除当前登录状态  
And 跳转到首页或登录页  
And 用户再次访问项目列表或工作台时应被要求登录  
And 不应继续展示私有项目内容

#### AC-F-004 未登录访问保护

Given 用户未登录  
When 用户直接访问项目列表、工作台、项目设置或版本历史  
Then 系统应跳转到登录页  
And 登录页应保留用户原本访问的目标页面  
And 登录成功后应返回目标页面  
And 在登录前不应展示任何私有项目内容

#### AC-F-005 登录失败提示

Given 用户输入不存在账号、错误密码、错误验证码或过期登录链接  
When 用户点击「登录」或「继续」按钮  
Then 系统不应跳转页面  
And 对应输入区域附近应显示明确错误信息  
And 错误信息不能只显示“失败”，应说明“账号信息不正确”“验证码已过期”或类似原因  
And 登录按钮应恢复可点击状态  
And 用户可以修改输入并重新提交

### 6.2 项目生成

#### AC-F-006 输入自然语言需求

Given 用户进入新建项目入口  
When 用户在输入框输入项目类型、目标用户、页面、风格或交互要求  
Then 输入框应保留用户输入内容  
And 系统应显示可提交状态  
And 用户可以继续补充多句需求  
And 用户提交后，原始需求应作为项目上下文保存

#### AC-F-007 生成多页面项目

Given 用户已输入有效自然语言需求  
When 用户点击「生成项目」  
Then 系统应进入生成中状态  
And 生成成功后应创建包含多个页面的项目  
And 左侧页面清单应显示生成出的页面  
And 当前预览区应展示默认首页  
And 项目应包含页面之间的主要跳转关系  
And 系统应创建初始版本快照

#### AC-F-008 生成中状态

Given 用户已提交生成请求  
When 系统正在生成项目  
Then 页面应显示生成中状态  
And 用户应看到阶段性说明，例如“规划页面”“生成预览”“保存项目”  
And 生成期间不应允许重复提交同一请求  
And 用户仍应能看到原始需求摘要  
And 如果生成时间过长，应显示仍在处理或超时提示

#### AC-F-009 生成失败重试

Given 项目生成失败  
When 系统返回失败状态  
Then 用户应看到明确失败提示  
And 原始需求输入不应丢失  
And 用户应看到「重试」入口  
And 用户可以修改需求后再次生成  
And 重试不应创建空项目或破坏已有项目

#### AC-F-010 生成结果保存

Given 项目生成成功  
When 系统展示工作台预览  
Then 项目应自动保存到当前账号  
And 项目列表应出现该项目  
And 工作台应显示「已保存」或等价状态  
And 初始版本快照应可在版本历史中查看  
And 如果保存失败，系统应提示用户重试保存

#### AC-F-011 需求为空时禁止提交

Given 用户的新建项目输入框为空或只包含空格  
When 用户点击「生成项目」或使用提交快捷键  
Then 系统不应发起生成  
And 输入框附近应提示“请输入项目需求”  
And 生成按钮应保持禁用或恢复可点击状态  
And 不应消耗额度或创建项目

### 6.3 项目预览

#### AC-F-012 实时预览

Given 用户打开已生成项目  
When 工作台加载完成  
Then 中间预览区应展示当前页面  
And 页面视觉内容应与当前项目版本一致  
And 顶部或预览区应显示当前页面名称  
And 用户执行修改成功后，预览区应更新到修改后的结果

#### AC-F-013 页面切换

Given 项目包含多个页面  
When 用户点击左侧页面清单中的某个页面  
Then 预览区应切换到该页面  
And 当前页面在页面清单中应有选中状态  
And 右侧对话上下文应显示当前页面变化  
And 切换页面不应清空对话历史或项目保存状态

#### AC-F-014 响应式预览

Given 用户打开已生成项目  
When 用户切换桌面、平板或手机预览模式  
Then 预览画布应切换到对应视口比例  
And 当前页面内容应在新视口中重新展示  
And 当前页面和项目版本不应改变  
And 如果切换失败，系统应保留上一个可用视口并显示提示

#### AC-F-015 页面加载失败提示

Given 用户打开某个项目页面  
When 当前页面预览加载失败  
Then 预览区不应只显示空白  
And 应显示失败提示、重试入口和返回其他页面入口  
And 用户可以打开版本历史恢复旧版本  
And 失败状态不应覆盖已保存项目

#### AC-F-016 空预览状态

Given 用户进入工作台但当前没有生成结果  
When 预览区没有可展示页面  
Then 预览区应显示空状态  
And 空状态应提示用户输入需求生成项目  
And 应提供示例提示词或新建入口  
And 不应显示报错式空白页面

### 6.4 对话式修改

#### AC-F-017 用户输入修改要求

Given 用户已打开一个项目  
When 用户在右侧对话面板输入修改要求  
Then 输入内容应保留在输入框中直到提交  
And 非空时提交按钮可用  
And 为空时提交按钮禁用或提示输入内容  
And 提交后用户消息应出现在对话历史中

#### AC-F-018 AI 根据当前项目上下文修改

Given 用户提交了修改要求  
When 系统执行修改  
Then 修改应基于当前项目版本  
And 不应从零创建一个不相关项目  
And 与本次修改无关的页面和内容应尽量保持不变  
And 修改成功后应生成新的当前版本

#### AC-F-019 修改范围识别

Given 用户提交修改要求  
When 系统识别修改范围  
Then 系统应判断范围是选区、当前页面、多个页面或整个项目  
And 对高风险范围应显示影响说明  
And 当选区和文字要求冲突时，应提示用户确认理解  
And 用户确认后才执行明显跨页面或破坏性修改

#### AC-F-020 修改结果预览

Given 修改执行成功  
When 工作台返回可编辑状态  
Then 预览区应展示修改后的页面  
And 对话面板应显示改动摘要  
And 摘要应说明改动页面或区域  
And 系统应显示新版本已保存或正在保存状态

#### AC-F-021 修改失败回滚

Given 用户提交修改要求  
When 修改过程失败  
Then 当前项目应恢复到修改前可用版本  
And 预览区不应展示半成品状态  
And 系统应显示失败原因和重试入口  
And 用户可以缩小修改范围或恢复历史版本  
And 不应生成误导性的成功版本快照

#### AC-F-022 修改历史记录

Given 一次修改成功完成  
When 系统保存修改结果  
Then 版本历史中应新增一条记录  
And 记录应包含时间、用户修改指令或系统摘要  
And 记录应说明影响范围  
And 用户应能在版本历史中预览该版本

### 6.5 点击选择后局部修改

#### AC-F-023 用户点击页面元素

Given 用户在工作台预览区开启选择模式  
When 用户点击文本、按钮、卡片、表单、导航或页面区块  
Then 系统应识别最合适的元素或区块  
And 被选区域应出现高亮或边框  
And 右侧面板应显示当前选区名称  
And 如果无法识别，系统应提示用户重新选择或改用文字描述

#### AC-F-024 系统显示当前选中元素

Given 用户已经选中元素或区块  
When 选区处于激活状态  
Then 预览区应持续显示选区高亮  
And 右侧面板应显示选区路径，例如“首页 / Hero 区块”  
And 用户应能清楚知道下一次修改默认作用于该选区  
And 切换到不包含该选区的页面时，系统应清除或提示选区失效

#### AC-F-025 用户输入针对该元素的修改要求

Given 用户已经选中页面元素或区块  
When 用户在对话面板输入局部修改要求并提交  
Then 系统应把选区作为默认上下文  
And 用户消息应显示选区标签  
And 修改成功后应更新该选区或相关直接区域  
And 修改结果应生成新的版本快照

#### AC-F-026 只修改选中范围

Given 用户选中了某个页面区块  
And 用户文字要求只描述该区块内部内容  
When 系统执行修改  
Then 系统应尽量只修改该区块及其直接相关内容  
And 不应无故重写整个页面  
And 不应无故修改其他页面  
And 如果必须影响选区外内容，应先提示原因和影响范围

#### AC-F-027 用户可以取消选择

Given 当前存在激活选区  
When 用户点击取消选择、退出选择模式或点击空白区域  
Then 选区高亮应消失  
And 右侧面板不再显示当前选区  
And 下一次修改应按自然语言判断范围  
And 取消选择不应改变项目内容

#### AC-F-028 没有选中元素时默认根据文字判断修改范围

Given 用户没有选中任何元素  
When 用户提交修改要求  
Then 系统应根据文字判断修改范围  
And 如果文字明确指向当前页面，则按当前页面处理  
And 如果文字明确指向整个项目，则提示全局影响范围  
And 如果文字含糊，系统应给出默认理解或要求确认

### 6.6 多页面管理

#### AC-F-029 查看页面列表

Given 用户打开多页面项目  
When 工作台加载完成  
Then 左侧页面栏应展示页面列表  
And 当前页面应有选中状态  
And 每个页面应显示名称  
And 如果项目没有页面，应显示页面空状态和新建页面入口

#### AC-F-030 新增页面

Given 用户打开已有项目  
When 用户点击新增页面并输入页面目标  
Then 系统应创建新页面  
And 页面清单应出现新页面  
And 页面地图应更新  
And 如用户要求导航入口，相关页面导航应同步更新  
And 新增成功后应生成版本快照

#### AC-F-031 删除页面

Given 项目中存在待删除页面  
When 用户点击删除页面  
Then 系统应显示二次确认  
And 确认弹窗应说明受影响的导航入口或跳转关系  
And 用户确认后页面从页面清单移除  
And 相关导航关系应更新或标记需要修复  
And 删除成功后应生成版本快照

#### AC-F-032 重命名页面

Given 项目中存在某个页面  
When 用户输入新的页面名称并确认  
Then 页面清单应显示新名称  
And 当前页面标题或路径应同步更新  
And 相关导航文案应更新或提示用户确认  
And 空名称或重复名称应显示错误并阻止保存

#### AC-F-033 设置首页

Given 项目包含多个页面  
When 用户将某个页面设为首页  
Then 项目默认打开页面应变为该页面  
And 页面清单应标记首页  
And 导出说明应使用该页面作为默认入口  
And 如果目标页面不存在，系统应提示设置失败

#### AC-F-034 页面导航关系维护

Given 用户新增、删除、重命名页面或修改按钮跳转  
When 页面关系发生变化  
Then 页面地图应同步更新  
And 预览中的导航或按钮应尽量指向有效页面  
And 对失效跳转应提示用户修复  
And 保存项目时应保存最新导航关系

### 6.7 版本历史与回退

#### AC-F-035 每次生成 / 修改形成版本快照

Given 项目生成或修改成功  
When 系统保存当前项目状态  
Then 版本历史应新增版本快照  
And 快照应能恢复对应预览状态  
And 快照应包含时间和触发说明  
And 快照创建失败时应提示用户

#### AC-F-036 查看版本列表

Given 项目存在版本历史  
When 用户打开版本历史入口  
Then 系统应展示版本列表  
And 每条版本应显示时间、名称或摘要  
And 当前版本应有明确标记  
And 没有历史版本时应显示空状态说明

#### AC-F-037 预览历史版本

Given 用户打开版本历史  
When 用户选择某个历史版本预览  
Then 系统应展示该版本预览  
And 当前项目不应立即被覆盖  
And 用户应能返回当前版本预览  
And 历史版本预览失败时应显示错误并保留当前项目

#### AC-F-038 回退到指定版本

Given 用户正在预览历史版本  
When 用户确认恢复该版本  
Then 当前项目应切换到该历史版本对应状态  
And 页面清单、预览、对话上下文摘要应与恢复结果一致  
And 恢复成功后应显示成功提示  
And 恢复失败时不应破坏当前版本

#### AC-F-039 回退前二次确认

Given 用户点击「恢复此版本」  
When 系统展示确认弹窗  
Then 弹窗应说明将恢复到哪个版本  
And 应提示当前未保存修改可能被覆盖  
And 用户点击取消时项目不发生变化  
And 用户点击确认后才执行回退

#### AC-F-040 回退后生成新的当前版本记录

Given 用户成功恢复历史版本  
When 系统保存恢复结果  
Then 版本历史应新增一条记录  
And 记录应说明“从某历史版本恢复”  
And 用户应能再次撤销或恢复到恢复前状态  
And 当前版本标记应更新到最新记录

### 6.8 导出

#### AC-F-041 导出当前项目

Given 用户打开已保存项目  
When 用户点击工作台顶部「导出」  
Then 系统应打开导出弹窗  
And 弹窗应显示当前项目名称和当前版本  
And 用户可选择静态文件或可继续编辑项目结构  
And 如存在未保存修改，系统应提示先保存或确认导出已保存版本

#### AC-F-042 导出成功提示

Given 用户确认导出  
When 导出成功完成  
Then 系统应显示导出成功提示  
And 提示中应包含导出类型和导出版本  
And 用户应获得下载、查看或继续工作入口  
And 导出成功不应改变在线项目内容

#### AC-F-043 导出失败提示

Given 用户确认导出  
When 导出失败  
Then 系统应显示明确失败原因  
And 用户应看到重试入口  
And 当前项目和版本历史不应丢失  
And 用户应能关闭弹窗返回工作台继续编辑

#### AC-F-044 导出内容说明

Given 用户打开导出弹窗  
When 系统展示导出选项  
Then 每个导出类型应有说明  
And 静态文件应说明适合查看、分享、离线保存  
And 可继续编辑项目结构应说明适合后续编辑或交给开发者  
And 系统应提示导出结果不等于生产应用

#### AC-F-045 导出前校验

Given 用户选择导出类型并准备确认  
When 系统执行导出前检查  
Then 系统应检查当前版本、保存状态、页面数量和原型限制说明  
And 有阻断项时应禁止导出并显示原因  
And 有非阻断提醒时应允许用户继续确认  
And 检查结果不应修改项目内容

### 6.9 保存与状态提示

#### AC-F-046 自动保存

Given 用户生成、修改、重命名页面或调整项目设置  
When 变更完成  
Then 系统应自动保存项目  
And 保存期间显示保存中状态  
And 保存成功后显示已保存状态  
And 保存失败时显示错误并保留未保存提示

#### AC-F-047 手动保存

Given 项目存在未保存修改  
When 用户点击「保存」  
Then 系统应进入保存中状态  
And 保存成功后显示已保存和保存时间  
And 保存失败后应显示失败原因和重试入口  
And 手动保存不应创建无意义重复版本

#### AC-F-048 保存中提示

Given 系统正在保存项目  
When 保存请求尚未完成  
Then 顶部或底部状态区应显示「保存中」  
And 用户应能继续查看当前页面  
And 关键离开操作应提示等待或确认  
And 保存超时时应进入保存失败状态

#### AC-F-049 已保存提示

Given 项目保存成功  
When 用户查看工作台状态区  
Then 系统应显示「已保存」或最后保存时间  
And 用户刷新页面后应看到保存后的内容  
And 离开页面时不应出现未保存提醒

#### AC-F-050 保存失败提示

Given 项目保存失败  
When 系统返回失败状态  
Then 状态区应显示保存失败  
And 用户应看到重试保存入口  
And 系统应提醒用户不要直接关闭页面  
And 失败状态不应清空当前编辑内容

#### AC-F-051 离开页面前未保存提醒

Given 当前项目存在未保存修改  
When 用户关闭页面、刷新页面或跳转到其他页面  
Then 系统应显示离开提醒  
And 提醒应说明可能丢失未保存修改  
And 用户可以选择继续离开或返回保存  
And 用户选择返回时应停留在当前工作台

### 6.10 P1 输入扩展、项目复制、额度与订阅

#### AC-F-052 图片上传预留入口

Given 用户在新建项目或修改面板查看输入能力  
When 用户看到图片上传入口  
Then 入口应标记为即将支持或后续能力  
And 不应让用户误以为 MVP 已支持完整图片理解  
And 如果用户点击入口，应显示能力说明和当前不可用状态  
And 不应消耗额度

#### AC-F-053 文件上传预留入口

Given 用户在新建项目或修改面板查看输入能力  
When 用户看到文件上传入口  
Then 入口应说明未来支持 PRD、Markdown、PDF、DOCX、JSON 等材料  
And MVP 不应承诺已能解析这些文件  
And 点击后应显示当前不可用或申请试用说明  
And 不应阻塞纯文本生成流程

#### AC-F-054 参考 URL 预留入口

Given 用户查看参考站点输入能力  
When 用户点击参考 URL 入口  
Then 系统应说明该能力为后续版本  
And 应提示只能参考信息架构、布局和风格  
And 应明确不复制第三方代码、文案、品牌资产或受版权保护素材  
And MVP 不应执行网页抓取闭环

#### AC-F-055 项目复制

Given 用户在项目列表或项目设置中选择复制项目  
When 用户确认复制  
Then 系统应创建一个独立副本  
And 副本名称应与原项目可区分  
And 后续修改副本不应影响原项目  
And 复制失败时应提示原因并保留原项目

#### AC-F-056 基础额度提示

Given 用户已登录  
When 用户查看账号区域、生成入口或高成本操作入口  
Then 系统应显示可用额度或使用次数状态  
And 用户应能理解生成、修改、导出等操作可能消耗额度  
And 额度不足时应阻止高成本操作并说明原因  
And 额度状态获取失败时应显示“暂时不可用”而不是错误空白

#### AC-F-057 基础订阅入口

Given 用户打开账号菜单或额度说明区域  
When 用户查看订阅入口  
Then 系统可以展示基础订阅说明  
And 如果 MVP 未开放真实支付，应明确显示“暂未开放购买”  
And 不应让用户进入无法完成的支付流程  
And 入口应说明未来订阅可能影响额度、项目数量、导出次数或高级输入能力

### 7.1 状态恢复原则

- 用户看见什么：每个失败状态都必须显示具体原因、当前项目是否安全、下一步可做什么。
- 用户可以做什么：失败后至少提供重试、返回工作台、恢复历史版本或修改输入中的一种。
- 系统下一步怎么恢复：优先保留最近可用版本，不用失败结果覆盖已保存内容。

## 8. 视觉风格与页面框架

### 8.1 视觉规范

| 维度 | 方向 |
|---|---|
| 整体风格关键词 | 简洁、克制、专业、安静、可信赖、温暖、留白充足 |
| 色彩方向 | 温暖浅色背景；主色低饱和；强调色用于 CTA、选区和重要状态 |
| 字体气质 | 清晰、现代、可读性强；标题稳重，正文轻量 |
| 圆角风格 | 中等圆角；卡片和输入框柔和但不过度可爱 |
| 按钮风格 | 主按钮明显、文字短；次按钮低对比；危险按钮使用明确警示色 |
| 输入框风格 | 大输入框优先；支持多行；提示语具体；聚焦状态清楚 |
| 卡片风格 | 细边框、轻阴影、浅色底；卡片只用于内容组或工具面板 |
| 页面间距 | 首屏留白充足；工作台区域紧凑但不拥挤；高频工具保持固定位置 |
| 图标风格 | 线性、轻量、语义明确；用于导航、导出、历史、保存、选择模式 |
| 预览区域风格 | 中心画布感，浅灰背景承托项目页面；当前页面边界清楚 |
| 对话面板风格 | 类聊天体验；用户消息、系统反馈、改动摘要有清楚区分 |
| 空状态风格 | 温和说明 + 示例提示词 + 主行动按钮；不使用夸张插画 |

### 8.2 登录页布局

- 页面背景使用温暖浅色。
- 页面主体采用左右分区或居中卡片布局。
- 左侧 / 上方为产品说明：产品名称、一句话定位、三条能力摘要。
- 登录卡片放在视觉中心，包含邮箱输入、登录按钮、可选第三方登录入口和条款提示。
- 错误提示显示在对应输入项下方或卡片内紧邻按钮上方。
- 加载状态体现在按钮和卡片内，不跳转到单独加载页。
- 移动端采用上下布局，登录卡片优先展示，产品说明收敛为短句。

### 8.3 工作台布局

- 顶部栏：项目名称、当前版本 / 保存状态、撤销、版本历史、导出、账号入口。
- 左侧项目 / 页面栏：页面清单、当前页面、页面新增、页面菜单、设置首页入口。
- 中间预览画布：当前页面预览、视口切换、选择模式切换、页面加载状态。
- 右侧对话修改栏：对话历史、当前选区、修改范围选择、输入框、提交按钮。
- 底部状态栏或保存提示：显示保存中、已保存、保存失败、生成中、修改中。
- 版本历史入口放在顶部栏或右侧面板固定位置。
- 导出按钮放在顶部右侧，与版本历史、保存状态保持同一操作区。

### 8.4 项目列表页布局

- 顶部：产品名称、账号入口、主按钮「新建项目」。
- 主区域：项目卡片网格或列表。
- 项目卡片显示名称、描述、最近更新时间、页面数量、版本数量、最近操作。
- 空状态显示一句说明、示例提示词和主按钮。
- 搜索 / 排序不进入 MVP 完整闭环；P1 支持按项目名搜索和按最近更新排序。

## 9. 信息架构

### 9.1 顶级导航

- 首页
- 登录 / 账号
- 项目列表
- 工作台
- 项目设置
- 版本历史
- 导出弹窗

### 9.2 页面层级

- 首页
- 登录页
- 项目列表页
  - 新建项目入口
  - 项目卡片
- 工作台
  - 页面清单
  - 页面预览
  - 对话修改面板
  - 版本历史弹窗
  - 导出弹窗
  - 项目设置页

### 9.3 项目内部结构

- 项目基本信息：名称、描述、默认风格、创建者、更新时间。
- 页面地图：页面列表、首页、页面用途、导航关系。
- 当前版本：当前可预览状态。
- 对话上下文：初始需求、修改历史、系统摘要。
- 版本历史：项目级快照列表。
- 导出记录：导出类型、导出时间、导出版本。
- 额度记录：生成、修改、导出等高成本操作记录。

### 9.4 页面与页面之间的关系

- 首页通常作为默认入口。
- 导航栏连接主要页面。
- CTA、卡片、列表项可以连接到详情页、表单页或功能页。
- 新增、删除、重命名页面时，页面地图和相关导航关系必须更新。
- 导出时应保留页面之间的跳转关系。

### 9.5 从登录到导出的完整路径

访问首页 → 点击开始生成 → 登录 → 项目列表 → 新建项目 → 输入需求 → 生成多页面项目 → 进入工作台 → 切换页面预览 → 对话修改 / 局部修改 → 自动保存版本 → 查看版本历史 → 回退或继续修改 → 点击导出 → 导出前检查 → 导出成功。

## 10. MVP 范围定义

### 10.1 MVP 必须做什么

- 轻量账号足够，但必须能区分用户身份并保护私有项目。
- 项目列表必须存在，因为需求文档已明确项目持久化和项目归属。
- 工作台必须完整闭环：生成、预览、修改、局部选择、版本、导出、保存状态。
- 多页面必须完整闭环：页面清单、切换、新增、删除、重命名、设置首页、导航关系保存。
- 版本回退必须完整闭环：项目级快照、列表、预览、二次确认、恢复、新记录。
- 导出必须完整闭环：导出入口、导出前检查、导出成功、导出失败。
- 额度限制至少需要记录和基础可见提示。

### 10.2 MVP 暂时不做什么

- 不做真实订阅支付。
- 不做团队协作。
- 不做公开分享。
- 不做复杂权限系统。
- 不做真正的设计系统导入。
- 不做 Figma 导入。
- 不做完整图片理解、文件解析、网页抓取。
- 不做任意框选区域修改。
- 不做局部页面回退或版本分支。

### 10.3 只预留入口的功能

- 图片上传。
- 文件上传。
- 参考 URL。
- 基础订阅入口。
- 项目复制。
- 搜索 / 排序。
- 公开分享。
- 团队协作。

### 10.4 需要完整闭环的功能

- 登录与访问保护。
- 项目生成与保存。
- 工作台预览。
- 对话式修改。
- 点击元素 / 区块局部修改。
- 页面管理。
- 项目级版本历史和回退。
- 导出。
- 保存状态和未保存提醒。

### 10.5 可以用简化方案的功能

- 账号：使用轻量账号，不要求复杂组织结构。
- 额度：记录和展示使用状态，不做真实支付扣费。
- 视觉风格：使用文本风格偏好，不做品牌资产库。
- 差异查看：先展示文本摘要和历史预览，不做复杂视觉 diff。
- 响应式预览：P1 支持三种视口，MVP 可先保证基础预览清晰。

## 11. 关键产品决策

| 决策点 | 推荐默认方案 | 原因 | 后续可能变化 |
|---|---|---|---|
| MVP 账号 | 轻量账号 | 满足项目归属和私有保护 | 后续支持 SSO、团队账号 |
| MVP 版本回退 | 整个项目快照回退 | 避免多页面状态不一致 | 后续支持页面级回退和分支 |
| MVP 局部修改 | 点击元素 / 区块 | 用户心智清晰 | 后续支持框选和层级面板 |
| MVP 订阅 | 不做真实支付 | 降低范围，先控制成本记录 | 后续做套餐、支付、账单 |
| MVP 分享 | 不做公开分享 | 避免隐私和权限复杂度 | 后续支持只读和可编辑分享 |
| MVP 输入材料 | 纯文本 | 聚焦核心生成闭环 | 后续支持图片、文件、URL |

## 12. 待确认问题

| ID | 问题 | 为什么重要 | 推荐默认答案 | 不同选择的影响 |
|---|---|---|---|---|
| Q-001 | 正式产品名称是什么 | 影响首页、登录页、导出说明和文档统一性 | 暂用 AI Design Workspace | 现在确认名称可减少后续文案替换；暂用名称可加快 PRD 推进 |
| Q-002 | MVP 轻量账号采用哪种登录方式 | 影响登录页输入项和错误状态 | 邮箱 + 密码或邮箱验证码二选一，先不强制第三方登录 | 第三方登录更顺滑但依赖更多；邮箱方案更通用 |
| Q-003 | MVP 额度是否对用户可见 | 影响工作台和账号菜单信息设计 | 可见基础额度 / 使用次数 | 只后台记录更简单，但用户难以理解限制；可见额度更利于成本预期 |
| Q-004 | MVP 是否必须有项目列表页 | 影响首次登录后的信息架构 | 必须有项目列表页 | 单项目工作区更简单，但不利于项目持久化和未来多项目管理 |
| Q-005 | 版本快照是否允许用户命名 | 影响版本历史交互 | MVP 支持自动摘要，用户命名作为 P1 | 用户命名更清晰但增加交互；自动摘要更适合 MVP |
| Q-006 | 导出可继续编辑项目结构是否需要指定目标工具 | 影响导出文案和用户预期 | MVP 不指定目标工具，只描述可继续编辑结构 | 指定目标工具会提高明确性，但容易变成实现选型决策 |
| Q-007 | 局部选择是否支持框选区域 | 影响预览选择交互复杂度 | MVP 不支持框选，只支持元素 / 区块点击 | 框选更自由但识别和范围判断复杂；点击选择更稳 |
| Q-008 | 响应式预览是否进入 MVP | 影响工作台预览控件 | P1 做桌面 / 平板 / 手机，MVP 先保证基础预览 | 放入 MVP 会提高产品完整度，但增加界面状态和验收范围 |
| Q-009 | 输入很模糊时先生成还是先补问 | 影响首次生成体验 | 默认先生成合理初版，关键缺口才补问 | 先补问更准确但流程慢；先生成更符合 AI 原型工具心智 |
| Q-010 | 是否需要内置项目模板 | 影响首页和新建项目入口 | P1 支持模板，MVP 用示例提示词替代 | 模板能提升上手速度，但会扩大内容维护范围 |
| Q-011 | 删除项目后是否可恢复 | 影响项目设置和危险操作 | MVP 二次确认后删除，不做回收站 | 回收站更安全但增加管理复杂度 |
| Q-012 | 是否需要生成内容版权提示 | 影响首页、导出、参考 URL 入口 | 需要基础提示 | 不提示会增加用户误用风险；提示过重会干扰流程 |
| Q-013 | 团队协作是否是明确商业方向 | 影响权限和订阅路线 | 先保留扩展空间，不进 MVP | 明确做团队会提前影响信息架构；暂缓更聚焦个人使用 |
| Q-014 | 公开分享是否需要提前设计入口 | 影响导出和项目权限 | MVP 不提供公开分享，仅预留待确认 | 提前做分享会增加权限、隐私和访问控制范围 |
| Q-015 | 修改前后差异需要多精细 | 影响版本历史设计 | MVP 做文本摘要 + 历史预览 | 视觉 diff 更直观但复杂度高 |
| Q-016 | 导出是否消耗额度 | 影响额度说明和导出确认 | MVP 记录导出行为，是否扣额度待确认 | 扣额度利于成本控制；不扣额度更符合用户预期 |

## 13. 文档输出与维护规则

- 本 PRD 适合直接保存为 `docs/PRD.md`。
- 后续实现前，应先确认第 12 节待确认问题中的高影响问题。
- 若需求变更，应同步更新 `docs/requirements.md` 或在 PRD 中标注版本变更记录。
- 本文档中的验收标准用于产品验收和 Issue 拆分，不代表具体测试代码或技术实现。
- 所有视觉描述只定义方向，不绑定具体设计系统、组件库或实现框架。
